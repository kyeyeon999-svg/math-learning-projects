# 사용 설명서

## 1. 시작과 종료
실행 중인 이전 서버를 Ctrl+C로 끝내고 start.cmd를 실행합니다. 브라우저에서 http://127.0.0.1:4190 을 엽니다. 실행 창을 닫으면 일기를 읽거나 저장할 수 없으므로 사용 중에는 열어 둡니다. 종료할 때는 작성 중인 일기를 먼저 저장합니다.

## 2. 교실에서 구구단 함께 배우기
허브 → 그림으로 배우는 구구단 → 한 묶음의 개수와 묶음 수를 선택합니다. 예를 들어 3개씩 4묶음을 고르면 동그라미 12개와 3×4=12를 연결해 설명할 수 있습니다. 상단의 ‘교실 크게 보기’를 누르면 문제·그림·보기 크기가 커집니다. 한 번 더 누르면 일반 보기로 돌아갑니다. 이 설정은 저장하지 않습니다.

## 3. 학생 개별 연습
1. ‘연습하러 가기’를 누릅니다.
2. ‘한 단씩 · 9문제’ 또는 ‘여러 단 섞기 · 10문제’를 고릅니다.
3. 한 단 모드는 2~9단 중 하나를, 여러 단 모드는 두 개 이상을 고릅니다.
4. ‘연습 시작’을 누르고 보기 네 개 중에서 답을 고릅니다.
5. 틀리면 묶음 그림과 힌트를 보고 다시 고릅니다. 정답을 고른 뒤 다음 문제로 이동합니다.
6. 결과에는 첫 시도 정답 개수와 처음에 틀린 식·정답이 나옵니다. 나중에 맞혀도 첫 시도 점수는 바뀌지 않습니다.

한 단은 ×1~×9가 각 한 번, 여러 단은 고른 모든 단을 포함한 중복 없는 10문제입니다. 다시 연습하기는 설정으로 돌아가 회차를 새로 시작합니다. 진행 중 허브나 설정으로 가려면 확인창이 나옵니다. ‘계속 풀기’나 Escape는 현재 문제를 유지합니다.

학습 기록은 저장하지 않습니다. 새로고침·페이지 종료 후에는 이전 점수·답을 되살릴 수 없습니다. 학생 이름·학번·학급·로그인은 받지 않습니다. 일기 저장과 구구단 학습 기록은 서로 별개입니다.

## 4. 일기 쓰기와 다시 읽기
허브에서 ‘나의 일기장’을 엽니다. 날짜·제목·오늘의 이야기를 적고 ‘일기 저장’을 누릅니다. ‘일기를 이 컴퓨터에 저장했어요’ 안내가 나오면 저장 완료입니다. 자동 저장은 하지 않습니다. 제목은 100자, 내용은 20,000자까지이며 빈 내용은 저장할 수 없습니다. 글자 표시·입력 제한은 JavaScript 문자열 길이 기준이므로 이모지 등의 표시 글자 수와 다를 수 있습니다.

목록에서 일기를 누르면 저장된 내용을 불러옵니다. 고친 뒤 다시 ‘일기 저장’을 누르면 수정됩니다. ‘새 일기’는 빈 작성 화면을 엽니다. 날짜별 여러 편도 작성할 수 있습니다. 검색은 제목·내용을 찾으며, 내용은 목록에서 최신 날짜부터 표시됩니다. 저장하지 않은 채 다른 일기로 이동하면 확인창이 나옵니다.

‘일기 삭제’는 확인 후 해당 일기를 제거합니다. 앱에 휴지통이나 복원 기능은 없으므로 필요한 일기는 먼저 백업합니다. 같은 일기를 여러 탭에서 수정했다면 오래된 화면의 저장·삭제를 거부합니다. 충돌 메시지가 나오면 현재 원고를 따로 복사한 뒤 목록에서 다시 열어 최신 내용을 확인하세요.

## 5. 일기 저장 위치와 백업
기본 DB 파일은 `%LOCALAPPDATA%\MathHub\diary-data\diary.sqlite`입니다. Windows 탐색기의 주소창에 `%LOCALAPPDATA%\MathHub\diary-data`를 붙여 넣으면 열 수 있습니다.

현재 PC의 실제 위치:
`%LOCALAPPDATA%\MathHub\diary-data\diary.sqlite`

프로그램 파일이 있는 OneDrive 작업 폴더와 별개입니다. 프로그램 파일만 복사해도 일기는 함께 복사되지 않습니다. 다른 로컬 폴더가 필요하면 서버 실행 전에 DIARY_DATA_DIR 환경변수를 지정할 수 있습니다. 폴더 변경은 이전 DB의 자동 이동을 뜻하지 않습니다.

백업: 일기 저장 완료 → 서버 종료 → diary-data 폴더를 원하는 백업 위치에 복사합니다. 복원: 서버를 종료한 상태에서 현재 DB도 별도 보관한 후, 백업한 diary.sqlite로 교체하고 서버를 실행합니다. 백업은 수동이며 백업 이후의 변경은 복원되지 않습니다. 실제 개인 일기의 백업·복원을 자동으로 수행하지 않았습니다.

로그인·암호화는 제공하지 않습니다. 이 컴퓨터의 같은 Windows 계정을 사용하는 사람이나 해당 파일을 읽을 수 있는 사람에게는 일기가 보일 수 있습니다. 학생별 독립 일기장이나 태블릿 간 동기화 기능은 아닙니다.

## 6. 새 앱을 바이브 코딩으로 추가하기
AI 코딩 도구에 다음처럼 요청합니다.

> math-hub에 새 학습 앱을 만들어 줘. dist 아래 별도 폴더로 구현하고 apps.js 목록에 추가해 줘. 기존 앱과 구구단의 비저장 정책을 유지하고 check.cmd로 확인해 줘. 새 앱의 저장 여부는 별도로 명시해 줘.

개발자가 수정할 최소 목록 항목:
```js
{ id: 'new-tool', title: '새 학습 도구', description: '무엇을 하는 도구인지 설명', href: 'new-tool/index.html' }
```
실제 파일을 dist/new-tool/index.html에 만듭니다. id는 고유한 영문 소문자·숫자·하이픈, href는 프로젝트 내부 HTML 경로입니다. art·badge·action은 선택 필드이며 생략하면 기본 그림·분류·버튼이 표시됩니다. 목록에 넣은 순서로 카드가 나옵니다. 기존 entries를 지우지 말고 배열에 항목을 추가하세요. 중복 id나 외부 주소는 거부하며 실제 파일 존재는 자동 테스트로 확인합니다.

추가 후 서버 재시작과 허브 새로고침 → 카드 실행 → 기존 앱 실행 → check.cmd를 확인합니다. 등록은 코드 수정 방식이며 화면에서 추가·삭제하지 않습니다.

## 7. 키보드와 화면
Tab/Shift+Tab으로 이동하고 Enter로 버튼을 누릅니다. 체크박스는 Space, 라디오 선택은 방향키를 사용합니다. 첫 Tab의 ‘본문으로 건너뛰기’로 주요 내용에 접근할 수 있습니다. 확인창은 취소 버튼에서 시작하며 Escape로 취소할 수 있습니다. 작은 화면에서는 세로로 스크롤하며 사용합니다.

교실 PC에 띄운 화면은 공유 수업용이고 학생 태블릿과 연결·동기화하지 않습니다. 현재 로컬 주소는 실행한 PC에서만 접속됩니다. 실제 태블릿에 접속 주소를 제공하려면 별도 배포가 필요하며 일기 DB를 인터넷에 그대로 공개하지 않습니다.

## 8. 다른 앱
알파벳 짝꿍 찾기는 A~Z 중 무작위 6쌍을 연결합니다. 틀리면 다시 선택하고 새 게임을 시작할 수 있습니다. 영구 기록은 없습니다.

PDF 글자 수 세기는 최대 100MB PDF 한 개를 브라우저에서 처리합니다. 공백 포함·제외·페이지별 결과와 추출 텍스트를 제공하며 스캔 이미지는 OCR하지 않습니다. 줄바꿈은 글자 수에서 제외합니다. NFC 정규화와 Intl.Segmenter를 사용하므로 편집기와 집계가 다를 수 있습니다. PDF.js와 관련 자산은 로컬 포함이며 vendor/LICENSE에 라이선스가 있습니다. 파일 선택·암호·복잡한 PDF의 실기기 종합 시험은 아직 남아 있습니다.

## 9. 문제가 생겼을 때
- 연결이 안 됨: start.cmd 창에 Local 주소가 보이는지 확인합니다. 이미 포트 사용 중이면 본인이 실행한 기존 서버를 끝내고 다시 실행합니다.
- 일기 서버를 다시 실행하라는 안내: 이전 버전 서버가 실행 중일 수 있습니다. 서버를 종료하고 start.cmd를 다시 실행합니다.
- 저장 실패: 작성 내용은 화면에 남습니다. 복사해 두고 서버 창·DB 폴더 쓰기 권한·디스크 공간을 확인한 뒤 다시 저장합니다.
- 화면이 예전 상태: 페이지를 새로고침합니다. 저장하지 않은 일기는 먼저 복사합니다.
- 다른 기기에서 일기가 안 보임: 정상입니다. 이 컴퓨터의 로컬 DB만 사용합니다.
- 실행 시 node:sqlite 오류: 현재 PC의 번들 런타임 또는 Node.js 24 이상을 사용합니다.

검증 실행은 check.cmd, 구체적인 결과와 제한은 FINAL-QA.md와 ACCESSIBILITY-QA.md를 참고하세요.
